## 适合交给它的工作

| 任务 | 主要成果 |
| --- | --- |
| 只读代码审查 | 有依据的可行动问题、准确位置、触发条件、影响和建议；没有发现就如实说明 |
| 故障诊断 | 预期与实际对照、最小复现、代码证据、已确认原因与待验证假设 |
| 明确要求修复 | 保留原有改动的最小修复，相关回归验证及真实结果 |
| 渐进重构 | 保持公共接口、错误路径、序列化和数据契约的小步修改 |
| 缺少仓库或执行工具 | 可审阅的补丁建议或定位步骤，并明确未读取、未应用或未运行的部分 |

对代码语义能够直接证明的错误，可说明“代码逻辑已确认（静态证明）”；运行复现和项目回归是否执行单独报告。性能收益需要真实基准，公共接口兼容不能只靠类型检查。普通本地可逆修复在用户已要求修复时直接推进；生产部署、数据写入等动作单独遵守实际授权和目标环境约束。

## 导入和开始使用

1. 在中台专家管理选择 **“从资源包导入” → “导入 YCPS / 完整包”**，直接选择上方 `.ycps.zip`。
2. 核对 code 为 `senior-software-engineer`、版本为 `1.0.0`、类型为 `EXPERT`；查看中英文字、标签、示例、表格、画布及三张图片。
3. 根据所在环境的版本流程完成导入后的试用。本包使用独立新 code；如果已经存在同名对象，应先核对身份和版本。
4. 提供实际仓库或代码片段，并区分“只审查”“修复”或“重构”。无需每次填完整表格，有明确代码和预期即可开始。

可从这两项开始：

> 请只审查这个模块的边界值和错误路径，不修改文件。每个发现指出触发条件与实际代码位置，没有确定问题就如实说明。

> 这个函数把合法的0当成默认值了。请先看仓库约定和已有改动，复现后最小修复，并验证0、null、未设置与正常值。保留公共接口，不部署。

包不会自动增加编辑器、代码执行、联网或账号权限，使用的是宿主实际提供并已授权的能力。
