# 微信公众号运营专家：任务交付模板

以下是按需取用的结构，不要求每次全填。状态只写本次实际完成的操作；方括号为待填写字段，不能照抄给用户。

## 定位与选题卡

| 字段 | 内容 |
| --- | --- |
| 服务读者 | [具体人群和使用场景；证据或假设] |
| 核心价值 | [读者读后能解决的一个问题] |
| 账号边界 | [不覆盖的话题、专业/商业边界] |
| 可用证据 | [原始文件、采访、数据、官方页面及读取日期] |
| 产能约束 | [采编人员、审核周期和真实可行的频率] |

每个候选选题再补：读者问题、可验证承诺、材料路径、待核事实、形式、预计工作量和优先级理由。热点与竞品仅作为线索，不能当用户账号已验证需求。

## 单篇稿件

1. **稿件状态**：[仅写稿 / 本地文件 / 后台草稿 / 已预览 / 已发表；附实际证据]。
2. **标题备选**：标题、所承诺的内容、与正文对应的位置、可能误导处；推荐一个。
3. **事实核对表**：主张、原始来源与定位片段、材料日期、状态（已核/冲突/待核）、稿中写法。
4. **可粘贴版**：标题、摘要、导语、二至四个短节、明确行动句；图片位以“【配图：用途；待确认版权】”标注。纯文本中的小标题和空行应在粘贴后仍可读，不依赖 Markdown 渲染。
5. **预览清单**：手机端标题、段落、数字、日期、链接、图片、署名、版权和行动句逐项检查；没有后台操作时全部标待办。

## 数据复盘

先填一张口径表：文章 ID、发表/群发、取数来源、取数日期、时区、统计开始与结束、是否去重、人数或次数、触达/曝光分母、渠道和受众。计算写出 `分子 ÷ 分母 × 100%`，避免混用群发触达与自然传播阅读。结论分三层：数据直接显示什么、有哪些合理但未证实的解释、下一次用哪些同口径数据检验。只有阅读人数时不给“标题有效”“转化率提升”的判断。若数据来自第三方工具，还要核对其字段定义与微信后台是否一致。

## 更正或发布请求

更正稿列原句、错误原因、经核对的新句、证据、需同步修改的标题/摘要/封面/正文及实际完成状态。发布请求先核目标账号、目标文章版本和授权范围；每个动作单独记真实回执。无法进入后台时交付终稿与人工步骤，不能说已经排期或发布。
