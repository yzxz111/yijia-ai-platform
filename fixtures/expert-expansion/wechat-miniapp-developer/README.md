## 适合交给它的工作

| 任务 | 主要成果 |
| --- | --- |
| 新增或调整页面 | 沿用现有栈的页面文件、注册入口、数据绑定、事件、加载/空/失败状态 |
| 交互与请求故障 | 触发条件、代码或运行证据、局部修复与相关回归 |
| 接口契约核对 | 请求/响应字段、HTTP 与业务状态、登录态、环境差异及未验事项 |
| 没有工程的学习任务 | 可复制最小示例、放置位置、前提与核查步骤 |

请求处理明确区分原生 `wx.request` 的回调与项目自有 Promise 适配器；收到响应后仍检查 HTTP 和业务结果。搜索输入变化时，旧成功、失败及完成回调均不得改变新请求状态；清空和页面退出也需使旧结果失效。只忽略旧结果不能声称真正取消了网络请求。

缺少 AppID、开发者工具、后端或真机时，仍完成可做的代码和纯逻辑检查，但不会把它们写成微信端通过。包本身不会增加宿主的文件、执行、网络、账号或发布权限。

## 导入和开始使用

1. 在中台专家管理选择 **“从资源包导入” → “导入 YCPS / 完整包”**，选择上方 `.ycps.zip`。
2. 核对 code 为 `wechat-miniapp-developer`、版本 `1.0.0`、类型 `EXPERT`；查看双语文字、三个示例、画布与图片。
3. 根据当前环境的版本流程试用；若已有同名对象，先核对身份与版本。
4. 提供实际工程或代码片段、预期行为与当前问题。有错误或接口契约时一并给出，无需每次填写长表格。

建议首次试用：

> 搜索词快速变化时，旧响应会覆盖新结果。请在现有工程修复，保留我已有的修改，覆盖清空输入、失败重试、旧回调和页面退出。分别列实际运行的检查与未做的微信端验证。
